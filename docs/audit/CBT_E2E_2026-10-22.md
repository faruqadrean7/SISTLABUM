## 1. RINGKASAN EKSEKUTIF

Berdasarkan pengujian komprehensif pada branch `feat/cbt-e2e-readiness`, telah dibuktikan secara empiris bahwa **siswa (`siswa.lab.001`) dapat mengerjakan ujian CBT dari awal sampai akhir di `apps/web` (portal siswa) menggunakan data nyata di database PostgreSQL**.

Seluruh rangkaian pengujian meliputi:
1. **Penyediaan Data Ujian Riil via Seeder (`CbtDemoSeeder`)**: 1 bank soal, 20 butir soal mencakup seluruh 6 tipe soal (PG, PG Kompleks, Benar-Salah, Menjodohkan, Isian Singkat, Uraian/Esai), 1 jadwal ujian aktif berdurasi 30 menit dengan token ruang ujian `DEMO30`.
2. **Automated Backend Feature Tests (Laravel)**: 11 skenario pengujian E2E (`CbtStudentE2EFlowTest.php`) dengan 344 assertion lulus 100% hijau tanpa kegagalan.
3. **Automated Frontend UI Flow (Playwright Chromium Headless Shell)**: Simulasi pengerjaan di browser riil mencakup login siswa, input token, pengerjaan, refresh halaman (state recovery), pemutusan koneksi internet selama pengerjaan (offline queue), pemulihan jaringan (resync tanpa duplikasi), deteksi anti-cheat tab-switch, dan submit akhir hingga muncul layar konfirmasi selesai.
4. **Pemeriksaan Keamanan Jaringan (Network Inspection)**: Terbukti 0% kebocoran kunci jawaban (`is_correct`, `match_key`, `correct_answer`) pada payload HTTP.

## 5. TEMUAN BUG & PERBAIKAN DALAM SCOPE

Sesuai aturan batasan tugas (*"jangan ubah logika CBT yang sudah ada kecuali untuk memperbaiki bug yang dibuktikan oleh test, dan sebut jelas di laporan"*), berikut adalah 2 bug yang ditemukan dan diperbaiki selama audit:

### [BUG-CBT-01] Kebocoran Kunci Jawaban pada Payload Soal Isian & Uraian
- **Severity**: 🟠 **HIGH (Security & Integrity Violation)**
- **File**: `apps/api/app/Services/Cbt/ExamSessionService.php` (baris 250–270)
- **Gejala / Bukti**:
  - `ExamSessionService::getSessionQuestions` sebelumnya langsung menyertakan array `$q->body` tanpa membersihkan atribut internal. Akibatnya, jika pembuat soal mendefinisikan kunci jawaban pada body (misal: `'correct_answer' => 'GUI'`), kunci tersebut langsung terkirim mentah ke browser siswa.
  - Untuk butir soal tipe `isian` dan `uraian`, `sanitizedOptions` sebelumnya tetap menyertakan entri opsi (padahal soal isian/uraian tidak memerlukan opsi pilihan untuk siswa).
- **Perbaikan yang Diterapkan**:
  1. Membersihkan atribut `correct_answer`, `is_correct`, `rubric`, dan `kunci_jawaban` dari `$sanitizedBody` sebelum di-return ke klien.
  2. Mengosongkan opsi pilihan (`$sanitizedOptions = []`) secara ketat untuk tipe soal `isian` dan `uraian`.
  3. Menambahkan atribut `text` pada objek opsi pilihan ganda (`is_array($opt->body) ? $opt->body['text'] : $opt->body`) agar label teks opsi dapat dirender sempurna oleh komponen UI `apps/web`.

### [BUG-CBT-02] Inkonsistensi Nilai Enum Status Ujian antara Seeder dan UI Web
- **Severity**: 🟡 **MEDIUM (UI Functional Blocker)**
- **File**: `apps/api/database/seeders/CbtDemoSeeder.php` & `apps/web/src/app/(portal)/portal/siswa/cbt/page.tsx:125`
- **Gejala / Bukti**:
  - Seeder awalnya menyetel status `'aktif'`. Namun komponen UI `StudentCbtCatalogPage` di `apps/web` memeriksa:
    `const isLive = exam.status === 'active' || exam.status === 'berlangsung';`
  - Perbedaan string ini menyebabkan kartu ujian di portal web menampilkan status "Menunggu Jadwal Mulai" dengan tombol pengerjaan nonaktif (disabled), sehingga siswa tidak bisa mengklik tombol untuk memasukkan token.
- **Perbaikan yang Diterapkan**:
  - Mengubah status ujian di `CbtDemoSeeder.php` menjadi `'berlangsung'`, selaras dengan konvensi migrasi database (`draft | dijadwalkan | berlangsung | selesai | arsip`) dan pemeriksaan antarmuka web.
